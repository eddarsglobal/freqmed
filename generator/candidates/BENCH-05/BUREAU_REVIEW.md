# BENCH-05 — Native Acoustic Backend & Real-Time Callback Engine

Candidat isolé basé sur BENCH-04 d9ba65bc0a4d5ef02838384242f78a11503511a0 (qualification propriétaire Mac PASS). RoadMap v1.1.0 ; P1.01/P1.02 PENDING, Bureau #54, PR #58. Préparation non émettrice autorisée par E ; aucune certification ni promotion.

## Implémentation
- File SPSC C11, un producteur/un consommateur, quatre emplacements de taille fixe alloués avant transfert. Index atomiques release/acquire, vérification atomic_is_lock_free à la création, aucune allocation/libération ou verrou explicite dans push/pop. Refus sur capacité saturée, lecture à vide ou dimensions invalides, arrêt collant. Pop à taille valide remet la destination privée à zéro en cas de refus. Ce contrat suppose une mémoire source/destination privée valide et non aliasée avec la file. La destruction requiert la fin et jonction des travailleurs ; stop n'est pas une barrière de quiescence, une opération déjà en cours peut se terminer et une copie déjà remise ne peut être rappelée. Pas d'affirmation de borne temporelle, de délai audio garanti, d'arrêt physique indépendant ou de sécurité temps réel certifiée.
- Raccordement natif dérivé de mac_transport.c BENCH-04, source exacte vérifiée. Le véritable moteur numérique et l'adaptateur BENCH-04 déposent deux blocs dans la nouvelle file puis récupèrent les données dans une AudioBufferList privée ; comparaison de tous les canaux avec le vecteur numérique d'origine, fermeture du moteur et guardian OFF. Ce parcours Mac utilise une file séquentiellement ; le test concurrent est distinct. Capture de propriétés réelles CoreAudio, aucune donnée microphone ni format de flux matériel négocié.
- Signature AudioDeviceIOProc vérifiée à la compilation macOS par pointeur de fonction typé. Fonction deny-only, retourne kAudioHardwareIllegalOperationError, ne lit ni n'écrit de buffers. Appel logiciel direct de la fonction avec arguments nuls vérifie le refus ; ce n'est pas une invocation par CoreAudio. Aucun appel d'enregistrement, démarrage ou ouverture de flux ; le consommateur numérique en RAM est séparé du callback de refus. Le moteur physique reste indisponible. Aucun changement de volume, aucun périphérique activé.

## Qualification effective
29 assertions C11 et 10000 blocs ordonnés entre deux vrais threads POSIX exécutés sous Linux avec -std=c11 -Wall -Wextra -Werror -pedantic -fsanitize=address,undefined -g -pthread. Sortie PASS, aucun diagnostic ASan/UBSan observé. Test de concurrence avec coordination d'un bloc à la fois ; les cas file pleine/vide, arrêt et dimensions sont testés séparément. Pas de ThreadSanitizer ni mesure de latence, ni stress à fréquence audio, ni preuve de conformité temps réel durcie. Identité des trois fichiers testés confirmée par git hash-object puis blobs GitHub : rt_queue.h 317646f92999e87239e54d6133f3563c862ac184, rt_queue.c 660672233fd4127a5acb0368e3a83308d226eb7b, test_rt.c 53caec107ff82b7552eb0952c80e00067fcf18c2. Vecteurs de copie numériques exclusivement, jamais des observations physiques. Le lanceur vérifie 33 blobs et compile deux exécutables temporaires. Compilation et exécution native Mac de BENCH-05 restent à faire. Aucun test historique répété, aucune installation. CoreAudio/CoreFoundation dépendances système.
