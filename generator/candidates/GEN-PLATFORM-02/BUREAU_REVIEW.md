# GEN-PLATFORM-02 — Native Hardware Capability Engine
Candidat préparatoire isolé sous clause E (interfaces P1.02/P2.01) ; P0.04/P1.03/P5.02 restent à leurs états officiels. Orientation propriétaire : exploiter Windows, Linux et macOS disponibles, sans émission dans ce candidat.

## Métadonnées
- macOS : réutilise quatre blobs historiques CoreAudio/IOKit épinglés. Pour chaque sortie audio visible avec format lisible : index local à l'instantané, nombre de canaux, taux nominal, indicateur de défaut et transport déclaré (built-in, USB, Bluetooth, virtuel, agrégé, autre ou inconnu). Un transport ne prouve pas l'existence ou les performances du transducteur. Les noms, UID et identifiants OS sont exclus du rapport. Le collecteur historique peut omettre des sorties dont le format est illisible et l'indicateur de défaut peut être faux si la requête échoue. Pas d'identité durable ni de snapshot atomique.
- Linux : PCM playback de /proc/asound/pcm, formats des flux déjà présents via hw_params (lecture de métadonnées uniquement ; pas d'ouverture PCM). Si fermé, absent, contradictoire ou illisible, format inconnu. USBTMC via descripteurs sysfs avec VID/PID de modèle si disponibles ; série : comptage des TTY associés à un périphérique. Pas de nom ou chemin exporté. Les vues conteneurisées peuvent être incomplètes.
- Windows : API MMDevice, énumération des endpoints render actifs, propriété PKEY_AudioEngine_DeviceFormat via IPropertyStore STGM_READ, rôle eMultimedia pour le défaut. Ce format configuré de mode partagé n'est pas une liste de formats supportés. Transport inconnu. Réutilise le collecteur PnP épinglé de PLATFORM-01 : compte des signatures et nœuds Ports, pas de détails individuels EM (PARTIAL). Aucun IAudioClient, pas de flux. Références : https://learn.microsoft.com/en-us/windows/win32/coreaudio/pkey-audioengine-deviceformat et https://learn.microsoft.com/en-us/windows/win32/coreaudio/enumerating-audio-devices.
- VID/PID USB identifient un modèle déclaré, pas un appareil unique, pas une preuve d'authenticité. Les signatures USBTMC ne qualifient pas un générateur. Les index sont locaux au rapport, pas des handles ni des identifiants persistants.

## Exécution
Python 3 ; Mac : Git et cc avec frameworks système ; Linux : Python seul ; Windows : Git, Windows PowerShell/PnP et g++ MinGW-w64 compatible avec les headers MMDevice (ou CXX compatible). Aucun téléchargement ou installation automatique. Les 18 tests sont des tests logiciels de parseurs/schéma, pas une simulation physique. --selftest n'interroge pas le matériel. Qualification native par OS non encore exécutée à la publication. PASS_PROFILE_SCHEMA_ONLY indique seulement la réussite des tests et de la validation du rapport, même si une vue est partielle ou indisponible. Ne pas interpréter un format nominal comme une bande acoustique garantie, ni une valeur numérique comme une intensité physique.
